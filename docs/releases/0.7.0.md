Aftermarket 0.7.0 adds **TOML** to AfterConfig (`aftermarket config`). An overlay can now change a vendor's TOML file the same way it changes JSON, YAML and `.env` files, without ever editing the file itself.

- **The whole of TOML 1.0.** Tables, arrays of tables, dotted and quoted keys, inline tables, every kind of string, integers in hex, octal and binary, floats, booleans, and the four kinds of date and time. A file TOML doesn't allow is refused with its line number, and the message never repeats the value, so an unquoted secret stays out of it.
- **Changes on the file's own lines.** A changed value is replaced where it stands, keeping the key, the alignment and the comment after it. Everything the overlay doesn't touch comes out byte for byte: comments, blank lines, `\r\n` line endings, even a missing final newline. Renames keep their line, and renaming a table rewrites only its headers.
- **Types stay put.** A date set from text in the same shape is still a date, a float set to a whole number is still a float, and a value that's already right keeps its spelling, so `0x1F90` stays `0x1F90`. The read-back before writing and `config test` both compare TOML types strictly.
- **When the lines can't take a change**, such as turning a table into a single value, the file is written again from its values. It still holds exactly the intended values, but without the comments.
- **`config diff` lists items one by one**, for every format, when a list keeps its length.
- **AfterHook reads TOML too.** A `.toml` file, or any file with `format: toml`, is watched field by field like JSON and YAML, with values under secret-looking keys sent as `REDACTED`.

The new `examples/vendor-app-toml` is a vendor app upgraded from 1.0 to 1.1. Seven changes apply on the 1.0 file and leave every other line as it was; on 1.1 the guards stop apply at the two lines where the vendor changed a default.

Also fixed: a JSON body nested more than 10,000 levels deep is now passed through as unreadable by patch, adapt and record, instead of being able to exhaust the stack.

Recorded results are in `test/results`. The full format is in `docs/config.md`.
