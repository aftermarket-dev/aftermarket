Aftermarket 0.9.0 adds **AfterBridge** (`aftermarket bridge`). Some software only hands its data over as files: a CSV export in a folder every night, a SQLite database nobody else is meant to open. AfterBridge serves those files as a read-only JSON API, so other programs can ask for `/orders?paid=false` or `/products/BK-001` instead of parsing them.

- **CSV exports and SQLite.** A source is one CSV file, the newest file in a folder by name (`orders-*.csv`), a SQLite table, or one fixed query. Columns can be typed (text, integer, number, boolean, date), renamed and left out.
- **Snapshots, never half files.** Each source is read into a snapshot in memory and read again when its file changes. A CSV file or `.sql` dump is read only once it has been left alone for `settle` (2 seconds by default) and only if it is complete: a final line break, every row whole, every value of its type, every key there once. Anything else is refused and logged, and the last good snapshot stays.
- **Lists and rows.** `/orders` with `limit`, `offset` and exact-match filters, `/orders/{id}` by key. GET and HEAD only; anything else 405; unknown parameters 400.
- **Requests never reach SQL.** The only SQL is the config's own, read through `sqlite3` read-only and in safe mode. A request only picks rows from a snapshot.
- **`bridge check`, `convert` and `test`.** Check every source once, write a source's snapshot to a JSON file, and run fixtures in the format the other tools use.

The new `examples/legacy-exports` has an old shop app's two nightly orders exports and its inventory, served as `/orders`, `/orders/{id}` and `/products/{sku}`.

SQLite sources need the `sqlite3` command, 3.37 or later; CSV sources need nothing else. Writes, logins (put AfterGuard in front) and joins across sources are not part of this release.

Recorded results are in `test/results`. The full format is in `docs/bridge.md`.
