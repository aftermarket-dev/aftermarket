Aftermarket 0.6.0 adds **AfterGuard** (`aftermarket guard`): a security gateway in front of an HTTP app that can't protect itself, such as an old admin panel with no login.

- **Rules you can read.** The same `when:` block as the other tools, plus client address ranges and credentials. The first rule that matches decides, and a request no rule allows gets 403.
- **Credentials.** API keys and HTTP Basic, kept in the config as SHA-256 hashes made with `aftermarket guard hash`, and compared in constant time. The app learns who called from a header AfterGuard sets, and never from one the client sent. The credential itself is removed before the request goes on.
- **Limits.** Rate limits per address, per client or per rule, a separate limit on failed logins, and caps on header size, body size, slow clients and connections. Limits live in a table of fixed size, and IPv6 addresses count by their /64, so a client can't fill memory by changing addresses.
- **Nothing that could be read two ways.** A request with both `Content-Length` and `Transfer-Encoding`, a folded header, an encoded slash or dot in the path, a `..` segment and similar tricks get 400 and never reach the app. They aren't cleaned up and passed on.
- **Headers.** Security headers added and version headers such as `Server` removed, by config. Headers that let a request rewrite its own path, method or address in some frameworks, such as `X-Original-Url`, never reach the app. Upgrades such as WebSocket pass only where a rule names them.
- **A log without secrets.** One JSON line per decision, with no credentials, cookies or query values, and floods of turned-away requests summarised once a second.
- **Commands:** `guard run` (with `--dry-run` to try a config on real traffic), `guard check`, `guard test` with fixture requests, and `guard hash`. HTTPS from certificate files is optional, and renewed files are picked up without a restart.

The new `examples/legacy-admin` puts an old admin panel behind AfterGuard: the debug page hidden, reports for the billing system's key, and the admin pages for the admin login from the office network only. What AfterGuard defends against, and what it doesn't, is in `docs/guard-threat-model.md`.

Recorded results are in `test/results`. The full format is in `docs/guard.md`.
