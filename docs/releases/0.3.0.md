Aftermarket 0.3.0 adds two tools that work as a pair: **AfterTest** (`aftermarket record`) and **AfterDiff** (`aftermarket replay`).

- **record** is a proxy that changes nothing. Every request and answer passes through byte for byte, and each finished exchange is written to a fixture file in the format `patch test` and `adapt test` already read.
- **Redaction.** `Authorization`, `Proxy-Authorization`, `Cookie`, `Set-Cookie` and `X-Api-Key`, and query keys such as `api_key`, `access_token` and `token`, are always saved as `REDACTED`. A config file can add header names, query keys and JSON fields by dot path, with `*` for any list element. The traffic itself keeps the real values.
- **Nothing unsafe is stored.** Bodies over `max_body`, binary bodies, compression other than gzip, cut-off bodies, upgraded connections and failed upstreams pass through and are logged as skipped. The fixture file is valid after every case, and record never overwrites one.
- **replay** sends each recorded request to two versions of a service, or to one and compares with the recording. It compares status codes, `Content-Type` and bodies. JSON is compared by meaning, key order and number formatting aside, and every difference is listed by path. `--ignore` leaves out fields such as timestamps.
- **Safe by default.** replay sends only GET and HEAD unless you pass `--include-writes`. `--set-header` puts real credentials back for the run.
- Markdown and JSON reports, and exit code 1 on any difference, for CI.

The customer-api example now shows the whole loop: the old client's twelve checks are recorded against v1, then replayed. Against v2 directly, all twelve answers differ. Against v2 through `aftermarket adapt`, all twelve are the same.

Recorded results are in `test/results`. The full format is in `docs/record.md`.
