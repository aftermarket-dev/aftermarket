The first release of Aftermarket, with its first tool: **AfterPatch** (`aftermarket patch`), a reverse proxy that repairs HTTP traffic between a client and a service you can't change, using rules you can read.

- `aftermarket patch run`: match on method, path, query, headers, status and content type. Set or remove headers, rewrite paths, and rename, copy, set or delete JSON fields in requests and responses.
- `--dry-run`: forwards traffic untouched and logs what every rule would change.
- An audit log of every change, as JSON lines, with no values in it.
- `aftermarket patch check`: validates a rule file and points out overlapping rules.
- `aftermarket patch test`: runs saved requests and responses through your rules and compares the results.
- Traffic no rule matches passes through byte for byte and streams. Bodies it can't change safely are passed on unchanged and logged.
- A single binary with no dependencies, for Linux, macOS and Windows.

Recorded test results and latency are in `test/results` in the repository. The full rule format is in `docs/reference.md`.
