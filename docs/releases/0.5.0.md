Aftermarket 0.5.0 adds **AfterHook** (`aftermarket hook`): it watches places that change without telling anyone, and sends a signed webhook for each change.

- **Four kinds of source.** A file, with JSON, YAML and `.env` changes listed field by field. A folder, with files added, changed or removed. An HTTP endpoint checked on a schedule. A command's output, which is how it watches a SQLite database through the `sqlite3` command, without a driver.
- **Changes by meaning.** A file rewritten with the same content, a change to an ignored field, or a folder file that was only touched sends nothing. A new row in a query result is reported as one added row.
- **Never half written.** A file is read twice before a change counts, and a JSON document that doesn't read waits for the next check. A file that disappears, or a structured file that loses more than half its size, is only reported when the next check sees the same, so a delete-and-write or a two-step rewrite sends nothing.
- **Delivery at least once.** Events are signed with HMAC-SHA256, kept in a state file, and retried with growing waits until delivered, in order, across restarts. A change found again after a crash keeps its event id, so a receiver can drop the repeat.
- **Secrets stay out.** Values under keys such as `password` or `token`, and passwords inside URLs, are sent as `REDACTED`, in text compared line by line too. The signing secret comes from the environment and never reaches the config, the state file or the log.
- **Commands:** `hook check`, `hook run` (with `--once` for cron and `--dry-run`), and `hook test` with before/after fixtures.

The new `examples/legacy-app` watches a status file, an exports folder and a SQLite table, and has a small receiver that checks signatures.

Recorded results are in `test/results`. The full format is in `docs/hook.md`.
