Aftermarket 0.4.0 adds **AfterConfig** (`aftermarket config`): overlays that change a vendor's config file without ever editing it.

- **Overlays.** Your changes to a vendor's config live in a separate file: `set`, `delete`, `rename` and `copy` by dot path, the same operations AfterPatch uses on JSON.
- **Guards.** A change can say what value it expects to find (`expect: 30`) or that a key must not exist yet (`expect_absent: true`). When an upgrade changes that value, `apply` stops, names the line and writes nothing, instead of quietly overriding what the vendor changed.
- **The vendor's file is never written.** `apply --out` writes the result to a separate file in one step, with the vendor file's permissions, and refuses any path that leads back to the vendor's file. A failed apply leaves the old output as it was.
- **Nothing else changes.** Fields the overlay doesn't name keep their place and exact value, and an overlay with nothing to change gives back the vendor's file byte for byte. JSON keeps its indentation and line endings. `.env` files keep every untouched line and every comment, and rewritten values are quoted so `$` is never expanded. YAML keeps unquoted values and keys exactly as written. Every result is read back before it's written.
- **Secrets stay out of sight.** `check`, `diff` and error messages show `REDACTED` for keys such as `password`, `token` or `api_key`, and for any path you list.
- **Commands:** `config check`, `config diff`, `config apply` and `config test` with fixtures.
- **Formats:** JSON, YAML (the subset the other tools read; comments are not kept in the output) and `.env`. TOML comes later.

The new `examples/vendor-app` has a vendor config at 1.0 and 1.1 and an overlay with seven changes. On 1.0 every change applies. On 1.1, which raised the default timeout and switched logging to JSON itself, apply stops at exactly those two lines.

Recorded results are in `test/results`. The full format is in `docs/config.md`.
